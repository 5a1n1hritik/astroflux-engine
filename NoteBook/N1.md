## Step 5: Physically Code the Drizzle Schema

Ab humne jo data model paper par design kiya tha (`stellar_targets` aur `light_curves`), use physically TypeScript code me badlenge.

`dashboard/src/` ke andar ek naya folder banayein `db` aur uske andar file banayein `schema.ts`.
Path: **`src/db/schema.ts`**

Isme hum strict Type-Safe layout code likhenge:

```typescript
import { pgTable, uuid, varchar, doublePrecision, timestamp, jsonb, index } from "drizzle-orm/pg-core";
import { relations } from "drizzle-orm";

// 1. Stellar Targets Table (Metadata Layer)
export const stellarTargets = pgTable("stellar_targets", {
  id: uuid("id").defaultRandom().primaryKey(),
  targetName: varchar("target_name", { length: 100 }).notNull().unique(),
  mission: varchar("mission", { length: 50 }).notNull(),
  starMassSolar: doublePrecision("star_mass_solar").notNull(),
  starRadiusSolar: doublePrecision("star_radius_solar").notNull(),
  createdAt: timestamp("created_at").defaultNow().notNull(),
  updatedAt: timestamp("updated_at").defaultNow().notNull(),
}, (table) => {
  return {
    // Highly optimized search index for target query searches
    targetNameIdx: index("idx_target_name").on(table.targetName),
  };
});

// 2. Light Curves Table (Time-Series Array Layer)
export const lightCurves = pgTable("light_curves", {
  id: uuid("id").defaultRandom().primaryKey(),
  targetId: uuid("target_id")
    .references(() => stellarTargets.id, { onDelete: "cascade" })
    .notNull(),
  // Storing pure float arrays processed from Python worker
  timeArray: jsonb("time_array").notNull(), 
  fluxArray: jsonb("flux_array").notNull(),
  createdAt: timestamp("created_at").defaultNow().notNull(),
});

// 3. Relational Mapping Framework (Drizzle Magic)
export const stellarTargetsRelations = relations(stellarTargets, ({ many }) => ({
  lightCurves: many(lightCurves),
}));

export const lightCurvesRelations = relations(lightCurves, ({ one }) => ({
  target: one(stellarTargets, {
    fields: [lightCurves.targetId],
    references: [stellarTargets.id],
  }),
}));

```

### Part 1: Local PostgreSQL Setup (Using Docker or Native)

Local testing ke liye aapke paas do sabse behtareen aur fast tarike hain:

#### Option A: Docker ke zariye (Mera Recommended - Instant & Clean)

Agar aapke system me Docker installed hai, to aapko kuch bhi alag se install karne ki zaroorat nahi hai. Ek single command se isolated Postgres container live ho jata hai.

Terminal me ye command chalaiye:

```bash
docker run --name astroflux-db -e POSTGRES_USER=postgres -e POSTGRES_PASSWORD=mysecretpassword -e POSTGRES_DB=astroflux -p 5432:5432 -d postgres

```

* **Kyun best hai?** Isse aapke operating system me kachra nahi hota. Jab testing khatam ho, container stop kar do.

#### Option B: Native PostgreSQL (Direct System Installation)

Agar aap direct installation chahte hain:

* **Linux (Ubuntu/Debian):** `sudo apt update && sudo apt install postgresql postgresql-contrib`
* **Mac:** `brew install postgresql@14`
* **Windows:** EnterpiseDB ki website se direct installer download karke run karein.

Installation ke baad, aapko `psql` command line ya **pgAdmin / DBeaver** (GUI Tools) ke zariye ek khali database create karna hoga jiska naam aap **`astroflux`** rakhenge.

#### Local Ke Liye `.env.local` Ki Setting:

Jab aapka local Postgres run ho raha ho, to aapne jo file `dashboard/.env.local` banayi thi, usme connection string ko aisa set kijiye:

```env
DATABASE_URL="postgresql://postgres:mysecretpassword@localhost:5432/astroflux"
PYTHON_WORKER_URL="http://127.0.0.1:8000"

```

### Part 3: Tables Ko Physically Create Kaise Karein? (The Migration Execution)

Ab chahe aapne local database connect kiya ho ya cloud ka database connect kiya ho, tables ko push karne ke liye Drizzle ORM me do tareeqe hote hain:

#### Tareeqa 1: `db push` (Prototype ke liye sabse tez)

Agar aap abhi local par hain aur jaldi se tables banakar check karna chahte hain, to bina migrations run kiye direct tables sync karne ke liye terminal me ye command chalaiye:

```bash
npx drizzle-kit push

```

*Yeh command direct `.env.local` wale URL par hit karegi aur check karega ki jo schema aapne TypeScript me likha hai, wahi same database me physically create ho jaye.*

#### Tareeqa 2: `migrate` (Production Standard)

Jo SQL file humne pichle step me `generate` ki thi, use database par strictly execute karne ke liye hum ek custom migration script likhte hain.

Hume ek database client instantiation file banani hogi jo connections ko live karegi.

Aap `dashboard/src/db/` folder ke andar ek nayi file banayein: **`index.ts`**
Path: `src/db/index.ts`

Isme ye setup code daal dijiye:

```typescript
import { drizzle } from "drizzle-orm/pg-proxy";
import { pgTable, uuid, varchar } from "drizzle-orm/pg-core";
import { pgClient } from "pg"; 
import * as schema from "./schema";
import { drizzle as drizzlePg } from "drizzle-orm/node-postgres";
import { Pool } from "pg";

// Connection pool configuration
const pool = new Pool({
  connectionString: process.env.DATABASE_URL,
});

export const db = drizzlePg(pool, { schema });

```

### Operational Checkpoint: What to do now?

1. Aap apne local system me local Postgres ko boot-up kijiye (Docker se ya direct installer se).
2. Apne `.env.local` me sahi credentials (username, password, port) set kijiye.
3. Terminal me `dashboard` directory ke andar khade hokar run kijiye:
```bash
npx drizzle-kit push

```



Jaise hi yeh command `Success` dikhaye, iska matlab aapka database physically active ho chuka hai aur tables structures ban chuke hain!

Kya aapka local database start ho gaya hai aur kya `drizzle-kit push` successfully execute ho gaya, taaki hum seedha **Next.js ke Backend API Tunnel Layer Route** ke code par kood sakein?

Docker container jo background me chal raha hai, use band (stop) karna bohot aasan hai. Aap apne terminal me niche diye gaye steps ko follow karke use band kar sakte hain:

### Step 1: Chal rahe container ki ID ya Name pata karna

Sabse pehle terminal me check kijiye ki aapka database container kis ID ya naam se chal raha hai:

```bash
docker ps

```

Yeh command aapko ek table dikhayegi jisme chal rahe containers ki `CONTAINER ID` aur `NAMES` (jaise humne pichle command me `--name astroflux-db` rakha tha) dikhayi degi.

---

### Step 2: Container ko band karna (Stop)

Aap do tarike se container ko rok sakte hain:

**Tareeqa A: Agar aapko naam yaad hai (Hamare case me `astroflux-db`)**

```bash
docker stop astroflux-db

```

**Tareeqa B: Container ID ka use karke**
Agar naam ki jagah aap ID use karna chahte hain (jaise `a1b2c3d4e5f6`), to chalaein:

```bash
docker stop <CONTAINER_ID>

```
